# Release v0.2.1

Hotfix release for the public fresh-install path. `v0.2.0` shipped the
schema-migration gate (ISI-7109, commit 63b899e9 landed on `main` AFTER the
`v0.2.0` tag was cut): the control-plane chart's pre-install hook Job
`ksquad-migrate` runs the apiserver image with `--migrate-only`, but the public
`ghcr.io/k8squad/ksquad-apiserver:0.2.0` image predates the flag
(`flag provided but not defined: -migrate-only`). A brand-new adopter following
the quickstart with default images could not install at all — internally masked
because internal installs pin registry images built past 63b899e9 (found during
ISI-7264 WS-1 fresh-install verification; tracked as ISI-7277).

## What ships

- Git tag `v0.2.1` on `main` → `build-images.yml` publishes **semver-tagged**
  images for the full component matrix at
  `ghcr.io/k8squad/ksquad-<component>:0.2.1`, including an apiserver whose
  `cmd/apiserver/main.go` defines `--migrate-only` (63b899e9 and everything
  after v0.2.0 — 756 commits).
- Control-plane chart (`config/helm`) `version`/`appVersion` → `0.2.1`. The
  default image tag falls back to `.Chart.AppVersion`, so an unpinned install
  resolves to `:0.2.1` images — public fresh installs complete again.
- CRDs chart (`config/helm-crds`) `version`/`appVersion` → `0.2.1`, and the
  control-plane chart's `k8squad.io/min-crds-version` annotation → `0.2.1`.
  Required: additive CRD schema changes since v0.2.0 (RolePool, EgressPolicy
  expansions, Project fields, Run fields) back features the 0.2.1 control plane
  reconciles. CRD changes are additive-only, so newer CRD charts are always
  safe.
- New CI lane `public-images-smoke` (nightly + dispatch): installs the
  PUBLISHED chart from charts.k8squad.io with PUBLIC default images only —
  no image overrides — on a fresh kind cluster, asserts the ksquad-migrate
  hook completes and every control-plane Deployment resolved to the chart
  appVersion tag. This exact surface had no lane before (getting-started-smoke
  leaves `controlPlane.enabled=false`; e2e builds images from source), which
  is how the 0.2.0 skew shipped invisible.

## Upgrade an installed cluster

CRDs first (ADR-0002, Option B):

```sh
helm repo add k8squad https://charts.k8squad.io && helm repo update
helm upgrade --install k8squad-crds k8squad/k8squad-crds --version 0.2.1
helm upgrade --install k8squad k8squad/k8squad --version 0.2.1 \
  <your install-time --set flags — controlPlane.enabled, database, model...>
```

Re-apply your install-time flags rather than `--reuse-values` (stale v0.2.0
chart defaults would carry forward; retrieve the user-set values you had with
`helm get values k8squad`). Public 0.2.0 installs with
`controlPlane.enabled=true` never completed (the migrate hook failed first),
so there is no in-place 0.2.0→0.2.1 public migration state to preserve —
internal installs on `sha-`/`main` images unaffected by the bug upgrade with
the commands above.

## Verify

After a fresh install on public defaults:

```sh
kubectl -n k8squad-system get job ksquad-migrate   # absent or Complete: hook succeeded
kubectl -n k8squad-system get pods                 # apiserver/operator/console Ready
```

## Out of scope

- No CRD removals or schema contractions (additive-only, ADR-0002).
- No chart API surface changes beyond the version bumps.
